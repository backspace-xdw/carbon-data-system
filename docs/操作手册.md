# 工业能碳协同管控平台 (IECSP) — 操作手册

> 版本:v2.0 · 适用:平台管理员 / 园区管理员 / 数据员 / 观察员

## 一、系统概述

**工业能碳协同管控平台 (Industrial Energy-Carbon Synergy Platform, IECSP)** 围绕「计量 → 核算 → 履约 → 预警 → 报送」五个环节,把能源消耗与碳排放纳入同一视角,帮助园区与排放主体实现:

- **计量点 (Meter Point)** 为最小数据单位,覆盖电/气/水/蒸汽/热/煤六类能源
- **排放因子库** 可按生效期版本化,核算可溯源
- **配额履约** 按年度+组织绑定,实时呈现使用进度与缺口
- **风险事件** 由规则引擎触发,支持流转与归档
- **监管报送** 内置政府能耗/碳排放上报通道,一键提交

**技术架构**:服务端采用 Fastify + TypeScript + Prisma(SQLite) + InfluxDB + MQTT,前端使用原生 HTML5 + ES2022 + Web Components + Canvas 自绘图表,实时消息走 WebSocket。

**默认账号**(种子数据):
- 平台管理员:`admin` / `Iecsp@2026`
- 数据员:`steward` / `Steward@2026`
- 观察员:`observer` / `Observer@2026`

## 二、账户与角色

| 角色编码         | 名称        | 主要能力 |
| --- | --- | --- |
| platform_admin  | 平台管理员   | 全部能力,跨园区 |
| park_admin      | 园区管理员   | 园区内组织/账户/因子/规则/配额维护 |
| data_steward    | 数据员       | 计量点维护、数据补录、事件处置 |
| observer        | 观察员       | 只读浏览全部数据视图 |

> 通过 `统一身份网关` 登录(/login.html),JWT Token 默认 7 天有效。首次登录后建议在右上角下拉中触发"修改密码"。

## 三、能碳驾驶舱

登录后默认进入 `能碳驾驶舱 (Cockpit)`。该页面包含:

1. **核心 KPI** —— 本年/本月 CO₂e、在线计量点、未处置风险
2. **本年逐月碳排放趋势** —— 折线图,鼠标悬停查看每月数值
3. **本年能源结构** —— 环形图,按能源类型占比
4. **本月碳排放构成** —— 柱状图,各类能源 CO₂e 贡献
5. **碳配额使用率** —— 仪表盘,带阈值分段着色

页面每 60 秒自动刷新,亦可右上角点击"刷新"主动拉取。

## 四、能源数据接入

模块 M03,支持:

- **历史曲线**:选择计量点、时间范围(6h/24h/7d/30d)、聚合粒度(5min/15min/1h/1d),曲线由 Canvas 自绘,鼠标悬停显示精确读数。
- **实时推送**:WebSocket `/ws` 通道,MQTT 上行数据落库的同时推送至浏览器,展示在底部"实时推送"表格(最多 20 条)。
- **手工补录**:数据员及以上角色可手工补录单点读数,支持指定时间。

> MQTT 接入约定:Topic = `iecsp/meter/<计量点编号>/reading`,消息 JSON = `{ "value": 数值, "ts": 毫秒时间戳 }`,服务端按计量点的"倍率"系数计算后写入。

## 五、计量点台账

模块 M04 用于管理计量点的全部档案:

| 字段 | 说明 |
| --- | --- |
| 编号       | 业务编号,唯一约束(如 M-E-001) |
| 名称       | 中文显示名 |
| 能源类型   | electricity/gas/water/steam/heat/coal |
| 所属组织   | 园区 → 企业 → 车间,三级树形 |
| 单位       | 默认按能源类型预填,可改 |
| 倍率       | 物理读数 × 倍率 = 入库值 |
| 位置       | 自由文本 |
| MQTT 主题  | 与上文 MQTT 约定一致,可置空(仅 HTTP 接入) |
| 状态       | active/paused/scrapped |

按钮"暂停"/"启用"用于临时切换计量点的接收状态,scrapped (已报废) 计量点不接收新数据。

## 六、碳足迹核算

模块 M05 分为左右两栏:

- **左栏:区间核算** —— 选择时间范围,后端会调用 InfluxDB 对每类能源做求和,再乘以当前生效的排放因子,得到 CO₂e (kg/t)。
- **右栏:排放因子库** —— 新增因子需选择能源类型、因子值、单位、生效起始、来源(如"生态环境部 2024")。同一能源类型可保留多个历史版本,核算时使用最新生效的版本。

> 内置默认因子(IPCC 2006 + 生态环境部 2024)在因子库为空时自动生效,可通过添加自定义因子来覆盖。

## 七、配额履约

模块 M06 围绕"履约年度"组织数据:

- 上方三块 KPI:配额分配 / 已使用 / 使用率
- 下方表格列出该年度下所有"组织 × 来源"的配额记录
- **新增/调整配额**:登记某组织在某年度的配额(允许多来源:政府无偿、市场购买、CCER 抵消)
- **触发结算**:服务端按当年实际碳排放总量,根据各组织配额占比反推"已用"列(占位算法,实际可对接行业核算结果)

使用率超过 85% 显示黄色预警,超过 100% 显示红色超额。

## 八、风险预警

模块 M07:

- **风险事件流**:筛选状态/严重度后,表格按发生时间倒序展示。Open(未处置) 可"认领处置",Acknowledged(处置中) 可继续"闭环"(可填写闭环说明)。
- **风险规则**:维护规则编号/名称/范围(meter/org/global)/指标(瞬时值/配额使用率)/操作符(gt/lt/...)/阈值/严重度/冷却时间。

> 规则触发后的事件会通过 WebSocket 推送至所有在线浏览器,弹出右下角 Toast,严重度=critical 时为红色,warning 为黄色。

## 九、监管报送

模块 M08:

- **准备新报送**:选择期次(YYYYMM 或 YYYY)、组织、通道(政府能耗/政府碳排放/MRV 核查),系统据此生成一份 JSON 报送快照(包含区间核算结果)。
- 报送进入 `pending` 状态。
- "提交":状态切换为 `submitted`,记录提交时间(此处为占位,真正对接政府平台 API 需补充网关)。
- "标记受理"/"标记驳回":根据政府平台回执手工标注最终状态。

## 十、组织账户

模块 M09(仅 park_admin 及以上):

- **组织树**:园区/企业/车间三层
- **账户**:新增、编辑、停用、重置密码;角色赋值
- **审计日志**:最近 200 条用户动作(登录、改密、CRUD 等),含 IP

## 十一、部署

```bash
# 1. 启动外部依赖(可选,仅当对接真实 MQTT/InfluxDB 时)
docker compose up -d influxdb mosquitto

# 2. 复制环境变量
cp .env.example .env

# 3. 安装、迁移、灌入种子
npm install
npm run migrate
npm run seed

# 4. 启动
npm run dev          # 开发热重载
# 或
npm run build && npm start
```

服务统一在 `http://<host>:7090`,前端与后端同源(后端用 `@fastify/static` 托管 web/ 目录),无需独立 nginx。

## 十二、与历史版本差异声明

本平台 (v2.0) 与同名 v1 (React+Express) 是独立实现,代码与历史完全无关:

- **架构**:DDD 四层 vs v1 平铺 MVC
- **前端**:原生 HTML5 + Web Components vs v1 React + Ant Design
- **后端**:Fastify + Prisma vs v1 Express + Sequelize
- **数据模型**:计量点/履约配额/风险事件/报送记录 等业务术语全部独立
- **接口路径**:`/api/v1/<domain>/<action>` vs v1 自定义

历史版本归档于 git 分支 `v1-archive`,tag `v1.0-original`。
